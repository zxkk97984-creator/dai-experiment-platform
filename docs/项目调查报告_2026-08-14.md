## 二、架构概览

**DAI 实验平台**：面向 AI 课程的一站式在线实验平台（课程学习 / 作业与考试判题 / AI 智能评分 / Notebook 交互实验 / 多档运行环境）。

```
Vue3 (Vite + Pinia + CodeMirror) ──nginx──▶ FastAPI (/api/v1, 18 个路由模块)
                                               │ MySQL 8（业务事实源）
                                               ├─ Redis（Token 黑名单/会话撤销/队列唤醒）
                                               ├─ judge_worker（判题 + 考试 + AI 评分队列）
                                               ├─ environment_builder_worker（环境镜像构建）
                                               └─ Docker 沙箱（无网络/只读/非 root/cap-drop-all）
                                                     + 持久 ipykernel（Notebook 交互实验）
```

- **生产编排** `docker-compose.prod.yml`：7 个服务（mysql / redis / migrate / api / worker / environment-builder / frontend）；一次性 `migrate` 服务先行迁移、API 依赖其成功后才启动（TASK-016）；全套 healthcheck、Redis AOF 持久卷、安全响应头（TASK-030）。
- **数据库**：27 个 Alembic 迁移；发布采用两步迁移链（迁移 A → seed basic 环境 → head，TASK-014/016）。
- **环境档位体系**（Phase 6）：档位 → 不可变环境版本 → 受控包版本 → digest 冻结运行镜像；生产只用 digest，不用 `latest`。
- **AI 评分**：DeepSeek 兼容 API + 固定公式 S = F60 + A20 + R10 + Q10（`DAI智能代码评分方案_V1.md`）；Rubric 锁版本、教师可覆盖；生产默认关闭（数据治理审批门，TASK-020）。

## 六、P0 / P1 / P2 问题

### P0 —— CI 红灯（已本地复现根因）

1. **MySQL 套件 48 失败**（本机全新库复现一致，27 分钟跑完）。根因分三类，均已取证：
   - **测试质量：SQLite 外键被关闭**。实测项目自建引擎连接上 `PRAGMA foreign_keys = 0`。大量测试硬编码父 ID 而不建父行——例如 `test_ai_rubrics.py::test_generate_rubric_creates_draft` 直接传 `question_id=1`；checkpoint1 用 `exam_id=10, student_id=100`；`test_op_metrics.py` 用 `rubric_id=1`。SQLite 不查外键所以通过，MySQL 直接 1452 失败。**这是 48 个失败的大头。**
   - **真实生产 bug**：`backend/app/api/experiments.py:232` 使用 `.nullslast()` 生成 `ORDER BY ... NULLS LAST`，**MySQL 8 不支持该语法（1064）**——学生实验目录按学习状态排序的分页接口在 MySQL 生产环境会直接 500。
   - **待排查**：`test_judge_worker_recovery.py::test_stale_running_exam_trigger_finalize` 恢复扫描 `running_reset=0`（疑为 MySQL 方言差异，如 rowcount/FOUND_ROWS 语义）；另有若干并发/队列测试未归类。
