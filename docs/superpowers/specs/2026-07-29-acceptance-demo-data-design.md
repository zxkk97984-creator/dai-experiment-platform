# DAI 验收演示数据与课程管理白屏修复设计

**日期：** 2026-07-29
**状态：** 已批准实施
**目标分支：** `AIpanti`

## 背景

本地环境目前只有一门极简 E2E 课程、一道作业题和一道考试题，不足以覆盖课程内容、作业、考试、代码判题和 AI 评分等核心验收场景。

同时，教师访问 `/teacher/courses/1/manage` 时页面完全空白。浏览器控制台已经确认直接原因是
`ChapterManageView.vue` 调用了 `useRouter()`，但只从 `vue-router` 导入了 `useRoute`。

## 范围

本轮实施包含：

1. 用组件回归测试固定并修复教师课程管理页白屏。
2. 新增可重复执行的验收数据脚本，通过系统公开 API 创建完整数据。
3. 创建两门课程、完整章节与课时、三份作业、两份试卷、两名学生和代表性代码提交。
4. 对含 AI 评分题目的作业和考试走真实发布流程，使 DeepSeek 生成并锁定评分量规。
5. 更新本地验收说明，并用自动化测试、构建、API 检查和真实浏览器完成验证。

本轮不重构现有课程、作业或考试业务，不删除原有 E2E 数据，也不把任何 API Key 写入代码、测试、日志或文档。

## 技术方案

### 1. 白屏修复

在 `ChapterManageView.vue` 的路由导入中加入 `useRouter`。修复前先新增组件测试，模拟：

- `useRoute()` 返回课程 ID；
- `useRouter()` 返回可观察的 `push()`；
- `coursesAPI.get()` 返回课程详情；
- `coursesAPI.getChapters()` 返回至少一个含课时的章节。

测试必须在修复前因 `useRouter is not defined` 失败，修复后验证课程名、章节名和课时名均被渲染。

### 2. 验收数据脚本

新增 `backend/seed_acceptance_data.py`，通过 `httpx` 调用 `/api/v1`，不直接写数据库。这样所有鉴权、所有权、发布校验、Rubric 生成、选课和判题路径都与真实网页一致。

脚本具备以下特性：

- 默认连接 `http://localhost:8080/api/v1`；
- 默认使用本地演示账号，密码可通过环境变量覆盖；
- 只以固定的 `[验收]` 标题和用户名识别自己管理的数据；
- 已存在的用户、课程、章节、课时、作业、题目和考试题全部复用；
- 对已存在的验收学生重置为约定密码，保证登录凭据确定；
- 若同名课程不属于目标教师，立即报出清晰错误，不接管他人数据；
- 发布前确保对象处于可编辑状态，补齐缺失题目后再发布；
- 对代码提交进行有界轮询，超时或失败时输出明确的对象 ID 和状态；
- 结尾打印创建/复用数量、关键 ID、账号和推荐验收入口；
- 绝不读取、打印或硬编码 DeepSeek API Key。真实 AI 调用由已运行后端的环境配置完成。

### 3. 固定演示账号

| 角色 | 用户名 | 默认密码 | 用途 |
|---|---|---|---|
| 教师 | `teacher` | `Passw0rd!` | 课程、作业、考试和成绩验收 |
| 学生甲 | `accept_student_a` | `Passw0rd!` | 正确/高质量提交 |
| 学生乙 | `accept_student_b` | `Passw0rd!` | 错误或部分正确提交 |

管理员账号只用于创建或修复验收学生，默认用户名为 `admin`。管理员、教师和学生密码均可由环境变量覆盖。

### 题目完整性

所有代码题都必须具备：

- 清晰的问题描述、函数名和函数签名；
- 可直接编辑的 starter code；
- 至少两个公开样例；
- 足以区分常见错误的隐藏测试；
- 明确的时间与内存限制；
- 指定的 grading mode。

所有选择题都必须具备完整选项、正确答案、分值和稳定排序。

### 提交数据

脚本为验收学生创建少量但有代表性的提交：

- 学生甲：至少一份 legacy 正确提交和一份 active 正确提交；
- 学生乙：至少一份 shadow 部分错误提交和一份 active 错误提交；
- 重复运行时，若同一学生对同一验收题已有提交，则不再次创建。

脚本等待这些提交进入终态，以便教师成绩页和 AI 复核页存在真实数据。

## 幂等与失败处理

脚本按“精确标题/用户名 + 父级对象”查询并复用数据。第二次执行不能增加课程、章节、课时、作业、题目、考试或预置提交的数量。

网络错误、登录失败、所有权冲突、AI Rubric 生成失败和判题超时必须产生可定位的错误。资源创建阶段失败时立即停止；代表性提交阶段允许汇总各提交结果，但最终只要存在失败就返回非零退出码。

## 测试与验收

自动化验证至少包括：

- `ChapterManageView` 组件回归测试；
- 验收数据结构数量和内容完整性测试；
- legacy/shadow/active 覆盖测试；
- 幂等查找或模拟 API 重跑测试；
- 前端完整测试和生产构建；
- 运行脚本两次，第二次数据库/API 计数保持不变；
- 后端健康检查和关键资源 API 检查。

真实浏览器验收至少包括：

1. 教师登录后打开验收课程管理页，页面非空，显示 3 个章节和 6 个课时；
2. 点击“添加章节”并取消，证明页面可交互且不污染数据；
3. 教师查看作业、考试、成绩或 AI 复核入口，存在真实题目与提交；
4. 学生登录后能看到已选课程、已发布作业和考试；
5. 全程没有相关 Vue 异常、错误浮层或关键请求失败。

## 安全与提交边界

- 不提交 `.env`、临时环境文件、API Key、测试缓存或用户原始方案文档；
- 不删除或覆盖原有 E2E 数据；
- 只提交本设计、实施计划、白屏修复、测试、验收数据脚本和对应 README；
- 按“白屏修复”和“验收数据”分别形成可审查提交。
