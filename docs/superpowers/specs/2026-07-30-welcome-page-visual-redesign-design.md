# 欢迎页视觉重构设计

日期：2026-07-30

目标页面：`/welcome`

实现范围：前端欢迎页，不新增后端接口

## 1. 目标与成功标准

欢迎页的首要任务不是解释单一功能或追求最低信息密度，而是以具有展示感的方式完整呈现 DAI 实验平台能力。页面应让访问者第一眼感到精致、动态、技术感强，并在一次连续浏览中看到课程、在线编程、Notebook、作业、考试、自动判题、AI 评分以及多角色工作台。

成功标准：

- 第一屏有明确的视觉焦点，并在不滚动时展示“代码运行 → 测试通过 → AI 评分”这一核心产品序列。
- 长页具有清晰的叙事节奏，不依赖大量同构卡片平铺功能。
- 页面保持明亮、通透、易读，同时通过深色产品窗口、渐变和动态状态制造科技感。
- 所有产品界面保持水平、垂直和网格对齐，不使用倾斜或旋转。
- 动效强化产品状态与空间层次，不妨碍阅读，也不造成眩晕。
- 桌面端与移动端均无裁切、横向溢出、意外换行或不可操作控件。

## 2. 已选视觉方向

采用“明亮科技展厅”方向。

视觉语言：

- 页面底色使用冰白与极浅蓝，提供空气感和清晰度。
- 钴蓝作为主行动色，紫色作为渐变和辅助强调色。
- 深海军蓝用于代码编辑器、运行结果等产品演示区域，形成明暗对比。
- 成功状态使用清晰的绿色，只用于运行成功、测试通过和正向评分。
- 通过大字号、紧字距标题、留白和产品窗口建立展厅感。
- 不引入外部图片、在线字体或依赖网络的素材。

核心色值：

- 页面底色：`#F8FAFF`
- 主色：`#2467ED`
- 辅助紫：`#7359ED`
- 深色产品窗口：`#14213B`
- 成功色：`#58DDA7`
- 主文字：`#13213A`
- 次级文字：`#6E7B92`

字体策略：

- 展示标题：`"Segoe UI Variable Display", "PingFang SC", "Microsoft YaHei", sans-serif`
- 正文与界面文本：`"Segoe UI Variable Text", "PingFang SC", "Microsoft YaHei", sans-serif`
- 代码：现有全局等宽字体栈

形状与层次：

- 按钮圆角：10px
- 产品窗口与主要展示容器圆角：16px
- 状态标签使用胶囊圆角
- 仅为重要产品窗口使用明显阴影；普通内容区主要依靠留白、分隔线和背景色区分

## 3. 页面结构与内容

页面按以下顺序组织：

1. 导航栏
2. 首屏产品舞台
3. 平台能力展区
4. 学习闭环
5. 多角色场景
6. 最终行动区与页脚

### 3.1 导航栏

导航栏使用半透明冰白背景和轻度模糊，保持粘性定位。

内容：

- 品牌：`人工智能实验平台`
- 锚点：`平台能力`、`学习闭环`、`角色场景`
- 主行动：`进入平台`

锚点平滑滚动到对应区块；主行动跳转至 `/login`。

### 3.2 首屏产品舞台

首屏采用左右双栏：

- 左侧为标题、说明和行动按钮。
- 右侧为严格正交对齐的代码运行窗口和 AI 评分窗口。

首屏可见文案：

- 辅助标签：`LIVE AI LAB`
- 主标题：`从代码开始，探索 AI 世界`
- 说明：`课程学习、在线编程、Notebook、自动判题、考试与 AI 评分，在一个持续运转的学习工作台里完整呈现。`
- 主行动：`探索平台能力`
- 次行动：`立即登录`

主行动滚动至平台能力展区；次行动跳转至 `/login`。

代码窗口展示一段完整、可读的训练与评估流程，包含约 10 行代码：

- 导入 NumPy 与数据集拆分工具
- 加载实验数据
- 拆分训练集与测试集
- 构建分类器
- 训练 20 个轮次
- 预测测试集
- 计算准确率
- 输出实验结果

代码窗口底部同时展示：

- `实验完成`
- `20 / 20 训练轮次`
- `98.6% 测试准确率`
- `全部测试通过`

AI 评分窗口在运行完成后进入，显示 `98.6`、正向趋势、评分进度和简短反馈。

### 3.3 平台能力展区

能力展区不使用八张同构卡片。它由一个主要产品展示面和若干辅助窗口构成：

- 在线编程实验：主要展示面
- 课程与课时：辅助窗口
- 交互式 Notebook：辅助窗口
- 作业、考试、自动判题与 AI 评分：横向综合窗口
- 实验模板与运行环境：作为能力说明或产品细节融入主展示面

悬停反馈保持正交：

- 模块向上移动 6–8px
- 边框使用对应强调色
- 阴影加深
- 一次性背景扫光
- 底部强调线展开
- 模块内部运行不同微动效，如进度填充、光点移动、波形变化或箭头位移

不使用旋转、倾斜或透视翻转。

### 3.4 学习闭环

该区块使用深海军蓝横向过渡带，为整页提供一次明显的明暗转场。

流程：

`学习 → 实验 → 提交 → 评测 → 进步`

每个节点对应：

- 学习：课程与课时
- 实验：在线代码与 Notebook
- 提交：作业与考试
- 评测：自动判题与 AI 评分
- 进步：结果反馈与复盘

一条发光路径随滚动进度点亮节点。静态或减少动态效果模式下，整条路径和全部节点直接可见。

### 3.5 多角色场景

该区块展示平台覆盖的四种角色：

- 学生：课程、实验、作业、考试与反馈
- 教师：课程建设、题目配置、成绩与 AI 评分复核
- 管理员：用户、课程与平台资源管理
- 开发者：实验模板与 Studio 工作台

场景使用真实产品结构的抽象缩略窗口，不使用纯装饰占位图。桌面端并列展示，移动端按学生、教师、管理员、开发者顺序堆叠。

### 3.6 最终行动区

最终行动区使用钴蓝到紫色的高饱和渐变收束页面。

文案：

- 标题：`让每一次实验，都成为看得见的成长`
- 说明：`从课程学习到 AI 评分，在一个平台完成完整实验闭环。`
- 行动：`进入实验平台`

行动跳转至 `/login`。

## 4. 动效系统

动效分为四层：

### 4.1 环境动效

- 背景网格和柔光缓慢漂移。
- 周期为 12–18 秒，移动距离较小。
- 不跟随鼠标制造大幅视差。

### 4.2 产品运行序列

首屏循环展示：

1. 代码逐行亮起
2. 运行状态变为成功
3. 输出结果出现
4. AI 评分面板进入并填充进度
5. 短暂停留后重置

完整周期约 7 秒。循环之间应有停顿，避免持续闪烁。

### 4.3 滚动动效

- 区块使用透明度和小幅纵向位移进入。
- 学习闭环的光轨随区块进入推进。
- 数值可以从较低值过渡到目标值。
- 单个滚动进入动画约 520ms，同一区块元素错开不超过 120ms。

### 4.4 交互动效

- 按钮和卡片反馈约 220–260ms。
- 能力模块悬停时抬升、扫光、强调线展开，并播放对应微动效。
- 焦点态与悬停态拥有一致的可见反馈。
- 触屏设备不依赖悬停才能理解内容。

所有动效遵守 `prefers-reduced-motion: reduce`。减少动态效果模式关闭循环漂移、扫光、逐行亮起和路径移动，但保留最终内容与清晰状态。

## 5. 组件结构

建议组件边界：

- `WelcomeView.vue`
  - 负责页面编排、登录跳转、锚点滚动和区块可见状态
- `WelcomeHero.vue`
  - 负责标题、行动按钮、代码运行演示和 AI 评分演示
- `CapabilityShowcase.vue`
  - 负责平台能力展示与悬停微动效
- `LearningFlow.vue`
  - 负责五步学习闭环和滚动点亮效果
- `RoleShowcase.vue`
  - 负责学生、教师、管理员和开发者场景

组件仅接收静态内容和可见状态，不依赖 Pinia 或后端接口。展示数据可以保存在 `WelcomeView.vue` 的常量中，通过 props 传入需要循环渲染的组件。

## 6. 数据流与交互

页面没有网络数据流。

交互流：

- 点击导航锚点或 `探索平台能力`：
  - 查找目标区块
  - 使用 `scrollIntoView({ behavior: "smooth" })`
  - 若目标不存在，保持当前页面，不触发错误跳转
- 点击任一登录行动：
  - 调用 Vue Router 跳转至 `/login`
- 区块进入视口：
  - `IntersectionObserver` 添加一次性可见状态
  - 动画完成后不重复触发
- 浏览器不支持 `IntersectionObserver`：
  - 所有区块立即设为可见

## 7. 错误处理与降级

- 不加载外部图片或字体，避免网络失败导致视觉缺失。
- JavaScript 动画初始化失败时，内容默认保持可见。
- 不支持 `backdrop-filter` 时，导航使用不透明冰白背景。
- 不支持 `color-mix()` 时，使用明确的边框和阴影回退色。
- 代码运行和 AI 评分均为欢迎页演示，不发送请求，也不暗示实时后端任务。
- 所有行动按钮均为原生按钮，并有可访问名称、键盘焦点和可见焦点态。

## 8. 响应式规则

桌面端：

- 目标验证视口：1280×720、1440×900
- 首屏左右双栏
- 能力区使用主展示面和辅助窗口的组合布局
- 多角色场景并列展示

移动端：

- 目标验证视口：390×844
- 首屏按标题、行动、代码窗口、评分窗口顺序堆叠
- 代码窗口完整显示，不横向裁切；长代码使用合理换行或缩短为移动端等价示例
- 能力模块使用双列或单列
- 多角色场景按固定顺序堆叠
- 关闭低价值环境漂移，保留运行结果和触控反馈
- 不出现横向滚动

## 9. 测试与验收

自动检查：

- `npm.cmd run build`
- 现有前端测试
- 为欢迎页增加基础组件测试，至少覆盖：
  - 关键能力文案渲染
  - 登录行动调用 `/login`
  - 平滑滚动目标存在时执行
  - 无 `IntersectionObserver` 时内容保持可见

浏览器验收：

- 页面 URL 与标题正确
- 首屏和完整长页均非空且无框架错误覆盖层
- 控制台无相关 error 或 warn
- 1280×720、1440×900 和 390×844 截图无裁切、重叠或横向溢出
- 首屏代码运行序列完成一次完整循环
- 四类能力模块悬停时均有可见且不同的微动效
- 键盘焦点能触发等价视觉反馈
- `prefers-reduced-motion` 下没有循环漂移或扫光，内容仍完整
- 主行动滚动至能力区
- 登录行动进入 `/login`

## 10. 非目标

- 不修改登录页、应用内仪表盘或后端接口。
- 不接入真实运行、判题或 AI 评分请求。
- 不新增第三方动画库。
- 不把图像生成结果作为生产页面资产；概念图仅作为实现参照。页面不引入外部插画或在线字体。
- 不改变现有认证与路由守卫逻辑。
